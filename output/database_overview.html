Key findings for the chatbot

  • Five tables, not three: catalogue, inventory, users, plus a chat_messages table already used to save conversations (and SQLite's internal sqlite_sequence).
  • Every product has exactly 6 size rows (XS–XXL) → 612 = 102 × 6. No orphan inventory, no product without inventory.
  • 145 of 612 size rows (24%) are at quantity 0 – but no product is completely sold out. The bot must answer stock per size, not per product.
  • garment_type is messy: 22 spellings for ~8 real categories (e.g. “short-sleeve t-shirt” vs “short-sleeve T-shirt” vs “t-shirt”). Search must normalise or use tags.
  • Price is set by category: tees $32, crewnecks $58, hoodies $68, quarter-zips $72, full-zip hoodies $88, jackets $98, a few $45 items.
  • colors and search_tags are JSON text – parse before filtering; “navy” and “navy blue” both appear.
  • Images: 102/102 image paths resolve to a real file in data/products/.
  • Passwords are hashed as pbkdf2_sha256$<salt>$<hex>; the backend must hash new sign-ups the same way.
