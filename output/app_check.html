A. Chatbot conversation

The shopper asks Handsome Dan specific questions. The answers must come from the live database, not be invented.

Check 1: Inventory count for a specific size PASS

What this proves: the chatbot answered "15 left in XS", exactly the quantity in the database's inventory table (XS = 15). The "✓ Checked live stock" badge shows it looked the number up with its check_stock tool instead of guessing.

The product card also shows every size's stock (XS ringed; S, M and L amber with 5 left; XL amber with 2; XXL in stock), which all match the database.

Check 2: Sold-out size and price PASS

What this proves: the chatbot clearly says the item is sold out in M (database: M = 0) and gives the real price of $68.00, along with the sizes that are in stock (XS, S, XXL). The badges show it checked live stock and catalogue prices.

The card repeats "Size M: sold out" in red, so the shopper can't miss it.

B. Dynamic search-result cards

A category question makes the agent search the catalogue and return structured matches. The website then draws these as product cards on the page.

Check 3: Category question triggers a catalogue search PASS

What this proves: the agent searched the catalogue and summarized it accurately: 25 hoodies, $45.00–$68.00, which matches the database's Hoodies category. It also tells the shopper the results are on the page, with a "12 hoodies are on the page · View" button.

The agent returns these matches in a structured page_results field (title, product ids, total). The backend turns those ids into full product cards from the database.

Check 4: Results appear on the page dynamically PASS

What this proves: without a page reload, the website added a "Handsome Dan found: Hoodies · Showing 12 of 25" section with product cards, built from the chat response. See all 25 links to the full Hoodies category, and Clear removes the results.

Check 5: Each card shows image, name, price and short info PASS

What this proves: each dynamic card has the product photo, name (Crew Left Chest Hoodie), price ($68.00), a short description, and a "1 size sold out" note. It uses the same card design as the Products page, so it looks appealing and consistent.

Check 6: A chat card opens the single-item detail page PASS

What this proves: clicking a card that the chat put on the page opens the same product detail page built in Problem 3 (large image, full description, price, sizes and stock). The search results shrink to a slim "Dan's results: Hoodies (12) · Show" bar so the product stays in view.

C. Usability features and interactive effects

The cart, guest checkout, recommendations and restocking (Problem 9), plus the bark, fly-to-cart bubble and growl (Problem 10).

Check 7: Add to cart: the bubble flies into the cart PASS

What this proves: clicking Add to cart creates a round bubble with the product's photo that arcs into the 🛒 cart icon. The cart badge updates to 1 and the page confirms "✓ Added 1 × size XS to your cart."

The animation is skipped automatically for shoppers whose device asks for reduced motion. For this capture the normal setting was simulated, because the test browser has reduced motion turned on.

Check 8: The cart shows what the shopper is ordering PASS

What this proves: the cart icon (badge 2) opens a cart listing each item with its photo, size, price, a quantity selector and Remove. The order summary shows a subtotal of $100.00 ($68 + $32), re-priced by the server from the database.

Check 9: Guest checkout (no account needed) PASS

What this proves: a shopper who isn't logged in can check out as a guest with just a name and email, choosing in-store pickup or shipping. A "Log in instead" link is offered but not required, and the site never asks for card details.

Check 10: Guest order is placed and confirmed PASS

What this proves: the guest checkout completes with order number CC-33FB9E and "(guest checkout)". In the database the order is saved with user_id NULL, and the hoodie's L stock went down from 8 to 5.

Check 11: Handsome Dan barks when the logo is clicked PASS

What this proves: a screenshot can't play sound, so a test overlay logged every sound the site played. Clicking the logo took the shopper home and logged "🐶 BARK (2 woofs)", and the bark waveform shows the two separate woofs.

The sounds are generated in the browser (Web Audio API), only play after a click, and can be muted with the 🔊 button in the nav bar.

Check 12: Handsome Dan growls when an item is removed PASS

What this proves: clicking Remove played the growl, logged as "🐶 GROWL (low rumble + 'rrr' wobble)" with its long, rumbling waveform. The T-shirt left the cart, so the badge is 1 and the subtotal is $68.00.

Check 13: Click history drives "Picked for you" PASS

What this proves: the site saved every product the shopper opened (the product_views table) and now shows "Picked for you · Because you've been looking at hoodies", with matching in-stock hoodies the shopper hasn't opened yet.

While testing, the label first read "Because you viewed 2025 Yale vs Harvard T Shirt" (the most recent click), which didn't match the hoodie picks. It was fixed to name the shopper's main interest.

Check 14: Low stock goes on the restock purchase list PASS

What this proves: after the guest order left the Basic Hoodie Big Yale at 5 in size L, the backend automatically added it to the business's purchase list with a reorder of 23 (back to 25, plus the 3 just sold). The list currently has 261 sizes / 6,122 units to restock.

This list is internal: the endpoint requires a staff key and isn't linked from the public site. It can also be exported to output/purchase_list.csv.

Automated checks run alongside these screenshots: scripts/check_agent.py 22/22 (chatbot honesty, search results, memory, recommendations) · scripts/check_shop.py 15/15 (cart, guest checkout, no overselling, restocking, recommendations) · scripts/check_auth.py 16/16 (accounts and password hashing).
